## Findings

### P2: Flash acknowledgement can override an invalidated RTC display record

Location: [`Renderer::new`](../src/appliance/render.rs), lines 28–43.

When the status bar is disabled, the timer-wake fallback loads the composed
digest from flash whenever the RTC digest is absent. An absent RTC digest also
means a refresh failed and may have altered the visible pixels. The fallback
therefore undoes the renderer’s deliberate invalidation.

Reproduction using the actual renderer and virtual panel:

1. Disable the status bar and successfully display a source, persisting its
   acknowledgement.
2. Simulate a cold boot; fail both its normal repaint and stock recovery at
   refresh BUSY. Verify the RTC record is cleared.
3. Simulate a timer wake with the same desired source and no valid RTC record.
4. The renderer reports `unchanged` and sends no repaint. A physical full
   baseline is required because the previous transfer failed.

The normal enabled-strip path does not use this fallback. Remove the fallback
to the flash acknowledgement and let the versioned RTC record determine whether
pixels can be trusted. A missing record should establish a baseline.

Evidence: `target/review-2026-11-07/reproductions.log`, test
`review_failed_barless_repaint_must_not_trust_flash_after_timer_wake`.

### P2: A manual image inherits validators belonging to another image

Location: [`Device::publish_frame`](../src/device.rs), lines 195–205.

After pulling image A with ETag A, uploading image B through the browser keeps
ETag A and Last-Modified A. `pull_snapshot` verifies that B is intact and sends
those validators. The server can correctly return 304 for A, leaving B on the
device through subsequent scheduled or manual pulls despite B never being the
validated server response.

The production storage reproduction pulls white with validators, publishes a
different black image locally, and observes that `pull_snapshot` still returns
the white response’s validators. Clear validators when a local publication
replaces the retained content with a different digest. A same-digest reupload
can preserve them.

Evidence: `target/review-2026-11-07/reproductions.log`, test
`review_manual_upload_must_not_reuse_another_frames_remote_validators`.

### P2: Successful 204/304 responses retain an obsolete pull error

Location: [`pull::update`](../src/pull.rs), line 142.

Only the 200 publication path clears `last_pull_error`. After a failed request,
a successful 204 or 304 resets the scheduler’s failure count but leaves
`/api/status.pull.last_error` reporting the old failure. A production-client
reproduction with a doubled SDK HTTP transport confirms both response codes
retain `previous timeout` despite `update` returning success.

Clear the diagnostic on every successful response, without requiring a frame
publication or a flash write.

Evidence: `target/review-2026-11-07/reproduction-pull.log`, test
`review_successful_no_content_response_must_clear_previous_pull_error`.

## Software ablations

[`tools/review_ablations.py`](../tools/review_ablations.py) copies production
sources and tests into a temporary directory, verifies the unmodified baseline,
then removes one behavior at a time. No mutated firmware is flashed. Each
experiment records its exact replacement, command, output, and exit status.
Compilation failures do not count as detected behavior regressions.

```sh
python3 tools/review_ablations.py \
  --output target/review-2026-11-07/ablations-final
```

Final result: **34 caught, 0 survived, 0 invalid experiments**. This is the
detection rate for these selected experiments, not an exhaustive mutation score.

The experiments cover stock polarity, short pulse length, unchanged-pixel
drive, cold initialization, timeout power-off, real old-image upload, window
extent, cleanup budget, idle exemption, unchanged-frame skipping, RTC record
validation, overlay clearing, minute changes, failed ADC samples, retained
cache validation, validator context, stored/uploaded digests, durable publication
ordering, restore replay, flash-free heartbeats, backup validation, USB input
bounds, USB awake protection, pull backoff, BTHome IDs, panel projection, OTA
digest/abort/image-validation/boot-selection ordering, transparency, dithering,
and browser status-area reservation.

The first 30-experiment run found a test gap: removing USB’s length limit
survived because the overflow test accepted any JSON error. The existing test
now checks the buffer bound and the exact overflow error. Production parsing
was already bounded; its implementation was not changed.

Added six [`OTA regression tests`](../tests/host/tests/ota.rs), exercising the
actual receiver with SDK doubles. They verify streamed data and short tails,
digest rejection, interrupted bodies, SDK write failure, empty images, missing
slots, SDK image rejection, and separation of staging from boot selection.
The four OTA ablations confirm that these tests detect removed safeguards.

## Board comparisons

Each valid firmware variant was installed through the authenticated OTA API and
confirmed in the other slot. The same checkerboard and inverse checkerboard
were uploaded in the same order; status-strip settings and source dimensions
were held fixed. The original image was restored before observing a minute
update. Times below are complete panel transactions reported by firmware,
including cold initialization and power-off, not isolated waveform duration.

| Variant | Main-image samples, ms | Minute update, ms | Minute mode |
| --- | --- | ---: | --- |
| Stock full | 2384, 2280 | 2280 | `full` |
| Stock window | 2309, 2331 | 2308 | `partial-window` |
| Stock-timing differential | 2277, 2341 | 2284 | `partial-differential` |
| Default short | 1393, 1474 | 1342 | `fast-window` |

This small run supports a transaction-speed improvement from the short
waveform. Windowing alone reduces the driven area and transferred bytes;
stock waveform timing still dominates. These samples are not a controlled
optical-density, power, temperature, or long-term ghosting measurement.

Every variant also passed duplicate-upload and hidden-pixel no-op checks:
changing only source pixels overwritten by the overlay reported `unchanged`,
zero milliseconds, and no extra physical transaction. Each minute update
used its expected mode without display errors or fallback.

An initial differential run stopped on an unsettled status assertion; its
cleanup restored the image and default firmware. The completed comparison
waits for a settled acknowledgement before sampling mode and counters. The
raw successful results are in `hardware-matrix.json`; no optical-failure claim
is inferred from the aborted harness run.

The differential profiles used about 37.8 KB free heap, versus about 43.5 KB
for the stock controls, consistent with retaining a 5,624-byte old-image plane.
Minimum free main-task stack was at least 13,804 bytes in the completed runs.

The final device runs the default short firmware. A fresh exported backup
matched the original source image and complete configuration exactly after
every completed variant and after cleanup. Backups and credentials remain
private and are not included in the report or source tree.

## Remaining limits

Physical battery-only wake/sleep, battery consumption, deliberate filesystem
power cuts, temperature extremes, optical contrast, and long-term ghosting
were not exercised in this USB-connected run. RTC wake behavior was simulated;
the first finding demonstrates why passing normal awake tests is insufficient.
Radio/TLS mechanics still depend on ESP-IDF; the review and successful OTA
transactions do not establish exhaustive network-failure coverage.

Recommended next changes are the RTC fallback fix, validator invalidation for
different manual images, and clearing successful-pull diagnostics. Each has a
reproduction above and should receive a focused regression before a fix.

## Follow-up cleanup

The pre-cleanup working tree was committed first. All three behavior findings
are now fixed, with regression tests observed failing before their fixes:

- Removed the flash-digest fallback and its unused renderer constructor
  argument. Only the validated RTC record can authorize a skipped wake.
- Consolidated frame publication into one durable state write. A different
  local image clears remote validators; a same-image reupload preserves them.
- Moved successful-pull acknowledgement to one path covering 200, 204, and
  304. The diagnostic clears in RAM; bodyless replies do not rewrite flash.

Removed the unused charging sprite, marker, and always-false charging argument.
The board has no measured charger-state input; USB retains its power-plug
indicator. Removed the obsolete power double from the renderer tests. The
stock waveform capture and all three comparison controls remain available.

Resolved both firmware-only lint errors and changed the OTA SDK double's label
to match the unsigned ESP32-C3 SDK field. CI now lints firmware for every variant
before building it, using the same feature arguments for both commands.

Completed host test counts are now 83 default, 74 stock, 74 window, and 79
stock-timing differential. Both host and firmware Clippy pass with warnings
denied for every variant. All four firmware builds and size checks pass; the
default image is 1,881,408 bytes, 304 bytes smaller than the reviewed image.
Browser unit checks, both Chromium integration tests, and formatting pass.

The ablation runner adds checks for manual validator invalidation and successful
pull acknowledgement. All 36 selected ablations are caught, with no surviving
or invalid experiments. Follow-up logs are under `target/cleanup-2026-11-07/`.

The cleanup firmware confirmed OTA in `ota_1`. Its initial `fast-full` took
1,355 ms and the following minute's `fast-window` took 1,346 ms, without
display or partial errors. The exported image and complete settings matched
a fresh private pre-cleanup backup. Minimum free main-task stack remained
13,804 bytes. Physical battery-only behavior retains the limits stated above.
